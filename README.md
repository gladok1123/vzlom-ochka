# Экран рядом

Приложение для **явного показа экрана по приглашению**. Основной сценарий: владелец запускает сессию на Linux, а гость смотрит её на Windows через отдельное desktop-приложение или браузер.

Это только просмотр: нет удалённых клавиш и мыши, командной оболочки, передачи файлов, скрытого доступа, автозапуска или записи видео. Владелец Linux сам выбирает, чем поделиться, и отдельно принимает запрос гостя.

## Быстрый запуск: Linux → Windows

### На компьютере владельца (Linux)

Нужны Node.js 20+ и `cloudflared` из официальных пакетов Cloudflare. Установите `cloudflared` в `PATH` и проверьте `cloudflared --version`, затем в корне проекта:

```sh
npm install
npm start
```

Откроется локальная панель владельца в актуальном Chrome, Edge или Firefox. Программа запустит временный Cloudflare Quick Tunnel и покажет ссылку `https://….trycloudflare.com` и код сессии. В панели нажмите «Начать показ экрана», выберите окно или экран и подтвердите запрос гостя.

Для Linux на Wayland может потребоваться работающий `xdg-desktop-portal`. Запускайте приложение от обычного пользователя, не от root.

### На компьютере гостя (Windows)

Получите у владельца **публичную ссылку и код**. Для запуска Windows viewer-приложения из исходников установите Node.js 22.12+ и выполните в PowerShell:

```powershell
npm install
npm run desktop:install
npm run desktop
```

В приложении вставьте ссылку, код и при желании своё имя, затем нажмите «Открыть просмотр». Запрос отправится владельцу Linux; видео появится после его подтверждения.

Чтобы собрать Windows-установщик на Windows:

```powershell
npm install
npm run desktop:install
npm run package:win
```

Установщик появится в `desktop/release/`. После установки Node.js и `cloudflared` для просмотра на Windows не нужны.

Гость также может просто открыть публичную ссылку в актуальном Chrome, Edge или Firefox и ввести код на странице. Windows-приложение — отдельный удобный клиент; видеосвязь к ОС не привязана.

## Linux-клиент

На Linux можно открыть ссылку в браузере или запустить desktop-клиент. Для AppImage:

```sh
npm install
npm run desktop:install
npm run package:linux
```

## Автоматическая публикация релиза

Workflow `.github/workflows/release.yml` собирает Windows NSIS-установщик и Linux AppImage и прикладывает их к GitHub Release при отправке тега `v*`. Например, для следующей версии:

```sh
git tag -a v1.0.1 -m "Экран рядом v1.0.1"
git push origin v1.0.1
```

## Другие команды

Локальный режим без Cloudflare Tunnel (удалённый гость подключиться не сможет):

```sh
npm run start:local
```

Отключить автоматическое открытие браузера владельца:

```sh
npm start -- --no-open
```

Порт локальной панели по умолчанию — `4173`. Чтобы изменить его:

```sh
# Linux
PORT=8080 npm start
```

```powershell
# Windows PowerShell
$env:PORT = 8080
npm start
```

## Как устроено подключение

1. `npm start` на Linux запускает локальную панель и Cloudflare Quick Tunnel.
2. Владелец передаёт гостю ссылку и код; код не помещается в публичную ссылку.
3. Windows viewer открывает HTTPS-страницу и отправляет запрос владельцу.
4. Только после подтверждения и выбора экрана браузер владельца начинает отправлять видео.

Параметры Quick Tunnel поддерживаются только для адресов вида `https://….trycloudflare.com`. Новая ссылка и новый код выдаются при каждом запуске.

## Приватность и ограничения

- Quick Tunnel — временный публичный адрес, а не постоянная корпоративная система контроля доступа. Передавайте ссылку и код только человеку, которому доверяете; не публикуйте их. Не отправляйте гостю локальную ссылку панели владельца — она содержит секретный ключ.
- Туннель используется для веб-страницы и сигнализации. Видео идёт напрямую между браузерами по WebRTC и шифруется средствами WebRTC; сервер приложения не получает и не записывает видеокадры.
- Для поиска прямого маршрута используется публичный STUN-сервер Google. Участники и STUN могут видеть сетевые метаданные/IP-адреса, нужные для соединения. В сетях со строгим NAT, VPN или корпоративными ограничениями прямой WebRTC может не установиться: TURN-релея в этой версии нет.
- Системный выбор экрана открывает сам браузер Linux после явного действия владельца. Отдельное окно безопаснее, чем весь экран. Трансляцию можно остановить в браузере или панели.
- Локальный сервер владельца привязан только к `127.0.0.1`; не открывайте его порт наружу.
